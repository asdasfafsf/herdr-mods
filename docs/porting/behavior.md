# 옮겨도 유지할 동작

기능을 만든 배경은 [catalog](catalog.md)의 WHY 링크가 기준이다. 아래는 그 배경을 반복하지 않고, 구현자가 추측하기 쉬운 입력·순서·예외를 보완한다. 코드 근거는 catalog와 각 절에 연결했다. ID별 합격 사례는 [acceptance](acceptance.md)에 있다.

## P01–P03: 프로젝트 진입

- Browse: 로컬은 폴더 선택, 원격은 경로 입력. 선택한 폴더가 레포 안이면 하나의 작업공간으로 연다. 레포 밖이면 바로 아래 한 단계의 `.git` 보유 폴더를 찾는다. 재귀 전체 검색이 아니다.
- 폴더에 레포가 여러 개면 UI는 처음 아무것도 선택하지 않고 목록·Pick all을 제공한다. 이미 열린 primary는 다시 열지 않는다. `hm add DIR`는 안 열린 레포를 모두 연다.
- 부모 폴더 기본값: 해당 머신의 마지막 선택 → 그 머신의 열린 primary들이 가장 많이 모인 부모 → 로컬 home(원격은 `~`).
- Clone 입력: Git URL, 부모, 머신. URL 마지막 경로에서 `.git`를 제거해 폴더 이름을 만든다. 부모가 없거나 목적지가 있으면 거부한다. 같은 머신·목적지로 시작한 clone은 60초 동안 중복 시작을 막는다.
- Clone은 새 작업공간의 **터미널**에서 실행한다. 성공하면 새 폴더로 이동한 셸, 실패하면 실패 메시지를 남긴 셸이 된다. 반환된 path는 예정 경로이며 clone 완료 증거가 아니다.
- New project: 정규화한 이름으로 새 디렉터리 → `git init` → `Initial commit` 빈 커밋 → 열기. Git 사용자 설정 부족 등으로 첫 커밋만 실패하면 폴더를 열고 `note`로 알린다. 기존 경로는 덮어쓰지 않는다.

근거: [project.js](../../lib/project.js), [project-add](../../mods/project-add/main.js).

## W01–W02: 워크트리 생성과 준비

입력은 레포/폴더, 표시 이름, 브랜치, base, 링크, 에이전트, 첫 메시지, setup, 추가 복사 패턴이다. UI와 CLI는 같은 생성 규칙을 쓴다.

1. Git 레포를 판별하고 primary/common-dir와 머신을 결정한다. 에이전트를 지정했으면 설치된 실행 argv를 찾고, 없으면 생성 전에 거부한다.
2. base 기본값: `origin/HEAD`의 전체 ref → 존재하는 `origin/main` → `origin/master` → `HEAD`. 명시한 base가 `#123`, `pr:123`, `/pull/123` URL이면 PR 정보를 조회한다.
3. 이름이 비었으면 PR 제목 → 링크의 GitHub issue 제목/티켓 키를 사용한다. 여전히 비었으면 오류. 표시 이름은 보존하고 폴더·기본 브랜치는 공백·경로 구분자 등 부적합 문자를 `-`로 바꾸고, 반복 점과 앞뒤 점/대시를 정리한다. 기본 브랜치/폴더 이름은 50자까지 줄인다. Git의 branch 형식 검사도 거친다.
4. PR의 head branch를 사용하되 사용자가 명시적으로 브랜치를 편집한 경우 덮어쓰지 않는다. 로컬 브랜치가 이미 있으면 그 상태로 checkout한다. 없으면 PR head를 origin에서 fetch하고, origin에 브랜치가 있으면 추적 브랜치를 만든다. 없으면 base로 새 브랜치를 만들되 base 추적은 설정하지 않는다.
5. 목적지는 기본 `~/.herdr/worktrees/<레포 이름>/<이름>`. 존재하면 `-2`, `-3`…을 붙인다. 로컬에서는 해당 경로의 Claude 프로젝트 기록이 남아 있는 경우도 재사용하지 않는다. 이름이 같은 서로 다른 레포의 충돌도 경로 충돌 검사로 피한다.
6. `git worktree add`가 성공한 뒤 복사·메타데이터 저장·작업공간 열기를 수행한다. 원격 base의 fetch 실패는 현재 코드에서 캐시 ref로 계속 진행할 수 있다. 이식 UI는 오래된 base 사용 여부를 숨기지 않는 것이 좋다.
7. `.worktreeinclude`와 추가 패턴에 맞는 **추적되지 않은/무시된 파일**을 primary에서 복사한다. 이미 목적지에 있는 항목은 보존한다. 추가 패턴은 쉼표·개행으로 분리한다. `#` 주석과 `!`로 시작하는 패턴은 무시한다(완전한 gitignore 문법이 아님). 슬래시 포함 패턴은 루트 기준, 없는 패턴은 각 경로 조각, 끝 `/`는 디렉터리 대상으로 매칭한다. macOS `cp -c -R` 실패 시 일반 `cp -R`을 사용한다.
8. setup·추가 패턴은 레포별 로컬 설정에 저장한다. setup을 레포가 임의 지정하는 설정 파일에서 실행하지 않는다. 로그인 셸에서 setup 성공 후 에이전트를 실행하고, 실패하면 에러와 셸을 남긴다. Claude·Codex 첫 메시지는 setup 뒤 argv로 전달한다.

기준 제한: 파일 복사는 로컬에서만 한다. 복사 helper 실패는 현재 생성 실패로 전파되지 않는다. Git 생성 뒤 단계가 실패해도 자동 rollback은 없다. 새 앱은 부분 완료를 식별해야 하며 성공한 checkout을 임의 삭제하지 않는다.

근거: [worktree.js](../../lib/worktree.js), [include.py](../../mods/worktree-plus/include.py).

## W03–W05: 메타데이터·삭제·정리

- 이름, 메모, 링크, PR, 작업 상태(`todo/in-progress/in-review/completed`), pin, unread, archive를 checkout의 머신·경로에 붙인다. 상태는 에이전트 실행 상태와 별개다. 빈 값으로 지우는 동작과 default로 되돌리는 동작을 지원한다.
- 링크는 HTTP URL이면 그대로, 티켓 문자열이면 설정된 `{key}` 템플릿으로 URL화한다. 템플릿이 없으면 텍스트다. 임의 트래커의 제목을 자동 조회하지 않는다.
- 행 메뉴: 편집, 상태, pin/unpin, 읽음, archive/unarchive, 세션, Finder/에디터 열기, 경로/브랜치 복사, 터미널, Sleep, 작업공간 닫기, 삭제. primary에는 archive·Sleep·삭제를 제공하지 않는다.
- 삭제 UI는 확인과 변경/서브모듈 경고를 보여준다. CLI는 이미 사용자가 요청한 것으로 취급해 확인 창 없이 진행하지만 변경·작업/승인 대기 중인 에이전트가 있으면 막고 이유를 반환한다. `--force`는 별도 명시가 있어야 한다. Git 상태 조회 실패를 깨끗함으로 취급하지 않는다.
- 삭제 실행은 작업공간을 닫은 다음 `git worktree remove`를 한다. Git 삭제 실패 시 이미 공간이 닫혔을 수 있다. 성공한 뒤 메타데이터를 제거한다.
- 브랜치 정리: `newBranch === false`이면 보존. PR이 merged라고 명시된 경우 squash merge도 정리 가능하다. 그 외에는 기록된 base(`#…` 제외) 또는 기본 원격 base에 포함됨을 ancestry로 확인한 경우만 지운다. `HEAD`만으로 삭제 판정하지 않는다. 기준 코드의 `newBranch` 미기록 처리는 [알려진 차이](#알려진-차이와-검증-한계) 참조.
- Clean은 origin fetch 후 secondary checkout만 조사한다. OPEN PR은 제외. MERGED PR 또는 base에 포함된 브랜치가 후보. PR이 merge 없이 CLOSED면 기본 미선택. tip commit 시간이 checkout 생성보다 오래된 “자기 커밋 없음”도 기본 미선택이며 변경/활동이 있으면 목록에서 제외한다.
- 변경·working/blocked·pin·Git 상태 실패는 정리를 막는다. UI는 후보별 선택, CLI `clean`은 기본 선택된 안전 후보만 순차 삭제한다. 성공 목록과 남은 이유를 함께 반환한다. `--review`는 UI를 연다.

## B01–B06: 레포 트리·이동·Sleep

- 레포 → primary → linked worktree → 터미널 구조. 열리지 않은 checkout도 흐리게 표시하고 클릭 시 연다. primary가 닫혀도 레포 묶음을 유지한다. 일반 폴더·머신 연결 상태도 호스트가 제공하는 범위에서 보인다.
- 레포/작업공간의 접힘과 보관 표시를 기억한다. 현재 선택으로 들어가면 펼치고 떠난 작업공간은 접는다. 외부 경로의 탭 선택도 트리에 반영하고, 현재 행이 화면 밖이면 스크롤한다. 드래그는 대상과 경계를 보여주며 머신 경계를 넘는 순서 변경은 하지 않는다.
- 정렬: activity(기본), recent, name, created. pin과 현재 상태 등 보조 정렬은 화면에서 일관돼야 한다. 다음/이전 이동은 보이는 순서의 **열린** 작업공간만 순회하고 끝에서 순환한다. 닫힌 checkout이나 접힌 worktree를 이동 과정에서 새로 열지 않는다.
- 표시 정보: branch/ahead-behind, PR/CI, 티켓, 메모, 포트, 작업 상태. PR 수집은 `@me`의 최근 60개 PR을 대상으로 해서 모든 작성자의 모든 PR을 보장하지 않는다. `gh`가 없으면 기록된 PR 번호만 표시한다.
- 로컬에서 checkout 폴더가 없어진 경우만 사라짐으로 처리한다. working 에이전트가 있으면 removed 표시를 하고 종료 후 공간을 정리한다. 원격 단절을 로컬 삭제처럼 처리하지 않는다.
- Sleep은 checkout 삭제가 아니다. 열린 공간의 Claude/Codex 세션 `{agent, session, argv, cwd, title}`을 먼저 저장하고 공간·터미널을 닫는다. checkout 행은 남는다. 열 때 첫 세션과 나머지 세션들을 이어 열고 잠든 표시를 해제한다. 지원 에이전트가 있는데 세션 ID를 식별하지 못하면 닫지 않고 실패를 알린다. `hm sleep`은 처리 결과를 기다린다. 지원 세션이 없고 일반 셸만 있으면 깨울 때 보통 셸을 연다. 공유 Codex 서버의 작업 중단을 보장하지 않는다. 이미 실행 중인 동일 세션은 LIVE 정보가 있으면 그 터미널로 이동한다.

## A01–A05: 에이전트 보기

- 기준 이후 성능 개선: 한 렌더의 pane/checkout/외부 행 metadata는 한 번 읽어 행끼리 재사용한다. 다음 렌더의 변경은 반영해야 한다. 같은 호스트 읽기가 행 수만큼 늘지 않는지는 [성능 회귀 검사](../render-performance.md)로 확인한다.
- Seen/ack/보기 옵션/레포 색도 렌더 스냅샷을 사용한다. ack 정리 결과를 같은 렌더에 반영하며 클릭·비동기 작업에는 렌더 스냅샷을 재사용하지 않는다. 기존 공통 UI 함수는 스냅샷을 생략하면 현재 공유 값을 읽는다.
- 살아 있는 하위 터미널은 렌더당 부모별로 묶고, 같은 에이전트의 자손 목록을 긴급도·행 생성에서 함께 쓴다. 원래 깊이 우선 순서와 트리 연결선을 유지하고 다음 렌더에서 종료·부모 변경을 반영한다.

- 우선순위 보기와 작업공간별 보기를 지원한다. 우선순위의 기본 상태 순서는 Needs you(blocked) → Done → Working → Seen → Idle. pin 묶음과 현재 탭의 Active 묶음을 별도로 유지한다. Active는 done이 되어도 현재 탭에 있는 동안 위치가 유지된다.
- 부모는 하위 에이전트의 긴급도를 반영한다. 하위 done은 부모에게 보고하는 완료라 독립적인 Done 소식으로 중복 계산하지 않고, error는 blocked로 취급한다.
- 바깥 Claude는 프로세스 registry, Codex는 TUI의 열린 rollout 또는 공유 서버의 열린 writer별 세션으로 탐지한다. 공유 서버는 원래 앱을 확정할 수 없어 `Codex server`로 표시한다. 호스트 안에 이미 표시된 세션은 중복 제외한다. 앱 태그/흐린 아이콘으로 바깥임을 표시한다. 클릭은 원래 앱을 종료하지 않고 새 앱에서 resume 또는 기존 터미널로 이동한다.
- activity는 기록의 끝을 읽어 실행 중 도구/허용 대기 명령/마지막 말·결과 첫 줄을 보여준다. 기록 변화가 없으면 재파싱하지 않는다. 두 번째 줄은 소식이 있을 때만 표시한다. 같은 이름이면 레포·브랜치로 구별한다.
- Seen은 호스트의 원래 상태를 바꾸는 새 프로세스 상태가 아니라 표시 상태다. done을 보고 idle이 된 시각 또는 `seen all`/특정 터미널로 확인한 시각부터 기본 120분. 다시 working이면 Seen이 아니다. 옵션 off이면 유지 기간은 0, 기간 입력은 5–1440분으로 반올림·제한한다.
- pin은 에이전트 목록의 pin과 checkout pin이 별개다. 수동 확인(ack) 또한 실행 중 작업을 종료하거나 새 응답을 보내지 않는다. 세 화면(사이드바·Agents·팔레트)이 같은 상태 변환을 사용한다.

## Q01–Q03: 검색 팔레트

- 기본 단축키 ⌘P/⌘J. 여러 단어를 순서와 무관하게 검색한다. 탭 외에 checkout 이름·branch·메모·티켓·PR 번호를 대상으로 한다. 닫힌 checkout도 결과로 열 수 있다.
- 보기: Needs you, Agents, Recent, Name, Docs. 선택한 보기를 기억하고 Tab으로 바꾼다. Needs you는 소식 있는 공간을 우선하며 조용한 묶음을 접는다. Agents는 공유된 에이전트 표시 순서를 쓰고 없으면 호스트 seq로 대체한다. Recent는 마지막으로 본 공간 시각, Name은 이름순이다.
- PR/issue URL 또는 `#123` 입력에 새 worktree 행을 제공한다. 일반 검색 결과가 없으면 입력한 이름으로 새 worktree를 만드는 행을 제공한다. 무조건 첫 결과를 자동 생성하지 않고 선택/Enter로 실행한다.
- worktrees 미지원이면 checkout/생성 행을 숨기고 기본 탭 검색으로 동작한다. Docs는 현재 pane의 repo 또는 폴더를 대상으로 파일 목록을 조회하고 문서 뷰어로 연다.

## S01–S04: 세션 목록·이어가기·이동·변환

- 로컬 Claude 프로젝트와 Codex rollout에서 세션을 찾되 Codex 현재 SQLite cwd·이름 기록을 우선하여 폴더에 속한 세션을 고르고 최근 수정순으로 정렬한다. primary 아래 다른 worktree 폴더의 기록은 exclude로 제외할 수 있다.
- 입력은 먼저 제목 필터다. 첫 검색 행을 선택하면 전체 메시지를 검색하고 snippet을 표시한다. 읽는 중/검색 중/없음/실패를 구분한다. ↑↓ 선택, Enter Resume, Alt+Enter Fork, Esc 닫기를 제공한다.
- Resume은 기존 ID, Fork는 새 세션을 만드는 CLI 옵션을 사용한다. 폴더와 실행 옵션을 보존한다. 목록에서 여는 경우 설치된 에이전트 실행 설정을, Sleep/복구에서는 저장한 원래 argv의 플래그를 사용한다. 기존 prompt·resume ID·continue 선택 옵션을 제거한 후 새 resume ID를 붙인다.
- `--into T`는 단순 UI 이동이 아니다. 실행 중 세션의 이동은 거부한다. Claude는 목적지 프로젝트 폴더로 transcript를 옮기며 cwd를 고치고, Codex는 열린 writer/rollout을 확인한 뒤 `deferred:true`를 반환하고 native `resume --cd 목적지`로 연다. Codex 기록·인덱스를 직접 고치지 않으며 같은 ID를 유지한다. 기본 이동은 원본 위치의 변경을 수반하므로 다른 앱으로만 바꿀 때 불필요하게 실행하지 않는다.
- `hm translate SESSION --to A[,B]`와 `resume --as A`는 `agent-session/1` 중간 파일을 거쳐 **새 ID**를 생성한다. 원본은 유지한다. 사용자/assistant 텍스트, 도구 호출·결과, compaction 요약을 옮기고 모델 고유 reasoning·서브에이전트·자동 삽입 지침은 제외한다.
- `resume --fork`는 `--into` 또는 `--as`와 함께 쓰면 거부한다. `--as A --into T`는 허용하며 원본을 이동하지 않고 대상 cwd로 새 에이전트 세션을 만든다.
- 도구는 대상에 native 실행 기록으로 재생하지 않고 텍스트로 기록한다. 결과는 20,000자를 초과하면 앞뒤 각 10,000자를 유지한다. 이미지는 placeholder만 남는다. 같은 역할이 이어지면 합치며, 마지막 user가 미응답이면 원래 답하기 전에 끝났다고 표기한다. 이 기능은 파일 형식 호환을 돕는 것이며 모델의 기억·이해가 완전히 같음을 보장하지 않는다.
- 원격 세션 목록/이동은 기준에서 지원하지 않는다. 다른 곳에서 개선 중인 버전이나 설치된 다른 플러그인의 형식을 이 기준에 섞지 않는다.

## R01: 재시작 복구

5초마다 런타임 pid·시작 추정 시각과 살아 있는 에이전트의 세션/argv/cwd/상태/공간/탭을 확인한다. 변경 시 `last.json`에 기록한다. 읽기 실패를 파일 부재로 간주하지 않고 실제 원자적 쓰기 성공 후에만 저장 캐시를 갱신한다. 쓰기 실패는 다음 주기에 재시도하며 같은 인스턴스의 런타임 전환 안내/자동 복원을 중복하지 않는다. 저장·조회·식별 문제와 회복은 `hm logs --restore`로 확인한다. 같은 PID이고 시작 시각 차이가 60초 미만이면 같은 런타임으로 본다. 창만 다시 그린 경우에는 복구하지 않는다. 런타임이 시작한 지 20초가 안 됐으면 판단도 기록도 하지 않는다(시작 직후 런타임은 터미널을 이전 run의 foreground로 보고한 뒤 셸을 다시 띄운다). foreground는 그 PID가 지금 해당 에이전트 명령을 실행할 때만 실행 중으로 센다.

새 런타임이면 기록 중 현재 동일 세션이 실행되지 않고, 원래 터미널이 비어 있는 셸이거나 사라진 것만 후보로 삼는다. 다른 앱에서 실행 중인 세션도 제외한다. 원래 터미널에서 다른 프로그램이 돌고 있으면 입력하지 않는다. 터미널이 없어졌으면 원래 공간이 남아 있는 경우 새 탭을 만든다.

Codex TUI가 rollout을 직접 열지 않는 공유 서버 방식이면 전체 제목·cwd의 유일한 일치와 열린 writer lock으로 식별한다. 공식 PID→ID 매핑은 아니며 중복·생략 제목이나 원격 클라이언트는 추측하지 않는다. 서버가 살아 있거나 확인 실패면 continue를 기본 해제하고 UI만 재연결한다.

기본은 복구 확인 창이다. 이전에 working이던 세션은 “어디까지 진행됐는지 먼저 확인하고 이어서 하라”는 메시지를 포함하는 continue가 기본 선택되며 항목별 해제 가능하다. 자동 복구 선택은 저장한다. 런타임이 바뀌면 이전 run 기록을 `previous.json`에 따로 보존하고, `hm restore`는 다시 묻도록 자동 설정을 해제한 뒤 그 기록 중 지금 실행되지 않는 세션을 다시 묻는다. 안내마다 기록 수·안내 수·제외 사유를 진단에 남긴다. 사용자가 정상 종료한 세션은 같은 런타임에서 다음 관찰 후 기록에서 빠진다.

## U01–U02: 사용량·한도

- 수집 화면은 30초마다 읽고, 각 CLI 직접 조회는 300초 캐시다. Refresh는 직접 조회를 요청한다. Claude 직접 조회와 Codex 직접 조회는 각각 최대 12초 응답 대기다. 모델 요청을 보내지 않는다.
- Claude: 직접 `get_usage`의 generic/model_scoped, 상태줄 raw, ClaudeHUD를 창 이름별 최신 시각으로 합친다. model-scoped Fable 0%도 유효하다. 새 generic-only 스냅샷이 기존 Fable 창을 지우지 않는다. `updated`는 표시된 창 중 가장 오래된 시각이다.
- 직접 조회 실패는 마지막 정상 값과 그 시각을 보존한다. Claude 캐시의 잠금으로 상세 창과 하단바의 중복 조회를 줄인다. 상태줄의 같은 reset 시각에서 더 낮아진 값은 이전 값으로 유지하지만 live 값은 그대로 허용한다. 이 둘을 섞을 때의 한계는 아래에 기록했다.
- Codex: 직접 조회와 최신 rollout 기록 중 더 최신 값. 네트워크 일시 오류는 조용히 유지하고 설치/로그인 등 지속 오류는 상세 표시한다.
- UI는 사용률이고 잔여율이 아니다. 80%부터 주의색, 100%부터 막힘색. reset 시각이 지나면 0%라고 단정하지 않고 `reset`으로 표시한다. 1시간 초과 데이터는 흐리게 표시하고 hover/detail에서 나이를 밝힌다.
- 모든 창의 이름·사용률·리셋까지 남은 시간을 표시하되 너비가 부족하면 설명 문구, 더 좁으면 막대·시간을 줄인다. 시간은 hover/detail에 남긴다. 현재 기준의 너비 예산은 `120 + 창수×180`, 최소형은 `120 + 창수×125` 미만이다. 이는 GPUI 기준 구현 수치이며 새 앱에서는 실제 텍스트 너비에 맞춰도 된다. 720px/4창에서 모든 사용률과 Refresh가 보여야 한다.
- 수동 Refresh는 helper 성공과 각 직접 조회 결과를 구분한다. 두 서비스 모두 성공하면 Updated, 일부 성공은 Partial, 모두 실패/응답 오류는 Failed. 마지막 정상 수치와 원래 시각은 보존하며 실패 이유는 hover로 표시한다.
- detail은 항목 수에 맞춰 높이를 늘리고 최대 600px에서 스크롤한다. 열어 둔 상세도 갱신한다.

## N01 / D01: 알림과 문서

- 알림은 초기 상태 읽기에는 보내지 않고 이후 전이를 비교한다. 앱이 활성 상태면 보내지 않는다. 새 blocked 전이, working→done/idle에 알린다. 같은 상태가 유지될 때 반복 알림하지 않는다. 지원 도우미가 있으면 클릭 시 해당 터미널로 이동한다. 도우미 실행 불가 때만 OS 스크립트로 대체하며, 대체 알림은 클릭 이동을 제공하지 않는다.
- 문서는 `.md/.markdown/.mdx`를 렌더링한다. 같은 머신·탭·파일이면 pane을 재사용한다. 사용자가 팔레트에서 열면 포커스 이동, 에이전트 명령이면 현재 입력 포커스와 보이는 탭을 보존한다.
- 로컬은 폴더 감시, 원격은 3초 폴링으로 따라간다. 1MiB 읽기 제한이 있다. Markdown 링크는 같은 pane에서 이동하고 Back 가능, http/https/mailto는 외부 열기, 다른 파일은 파일 위치 표시다. 알 수 없는 URI scheme은 실행하지 않는다. MDX는 코드 실행이 아니라 Markdown 입력으로 취급한다.
- Docs 목록은 Git tracked/untracked 중 ignore 제외, 비레포는 숨김 폴더·node_modules를 제외한 5단계. 최대 3000개 후보를 최근 수정순 정렬한다.

## C01–C02 / I01–I02: 명령·설정·설치

- CLI 전체 표와 값은 [integrations.md](integrations.md), 옵션 기본값은 [data.md](data.md) 참조. 대상 생략은 실행 cwd에 포함되는 가장 깊은 checkout → 현재 표시 공간. 이름은 대소문자 무시 exact 우선 후 부분 매치, 후보가 여러 개면 거부하고 repo/name 또는 경로를 요청한다.
- CLI와 UI는 같은 업무 함수와 저장소를 사용한다. 사람이 요청한 CLI 작업은 모달을 띄우지 않고 결과/오류를 반환한다(명시적인 `--review`, `restore` 등 UI 요청은 예외). 모듈 미지원이면 설치/연결할 기능을 알려야 한다.
- 설치는 선택한 번들만 복사한다. 소유 표시 없는 기존 파일/mod/스킬은 덮어쓰지 않는다. 단축키 충돌은 기본 보존, `--replace-keys`일 때만 대체. 기본 레이아웃은 복제하고 개인 레이아웃의 필요한 블록만 변경한다. 설정 변경 전 백업, dry-run 지원, 제거는 수동이다.
- 설치는 임시 폴더 검사 후 mod별 백업·교체·재검사를 한다(검사당 30초). 교체/재검사 실패 시 그 mod의 이전 파일을 복구한다. 실패나 비소유 mod로 인한 건너뜀이 있으면 exit 1로 설정·명령 변경 전에 멈춘다. 앞서 성공한 mod까지 되돌리는 전체 트랜잭션은 아니다.
- 공유 lib는 mod 폴더마다 필요한 것만 복사한다. 이 방식은 Herdr import 제한 때문이다. 새 앱에서는 같은 라이브러리를 직접 공유할 수 있으면 복사할 필요가 없다.
- 업스트림 기본 mod 변경은 원본 사본과 버전을 기준으로 3-way 병합한다. 새 앱의 공식 확장 API로 구현했다면 해당 앱의 버전 호환 검사로 대체한다.

## 알려진 차이와 검증 한계

기준 이후 추가된 C03(`hm logs`)는 [UI 진단](../ui-diagnostics.md)의 기록·중복 억제·실패·보존 규칙을 따른다. 렌더 VM과 독립된 프로세스에서 수집하고 오류 관찰과 실제 기능 회복을 구분한다.

`hm logs --render`의 시간 계측은 mod 내부 메모리 집계 + 렌더 밖의 60초 묶음 저장이다. 7개 구간, 25ms 이상 완료, 최악 1건·최신 8건, 미완료 마지막 구간을 보존한다. 미완료 이후 대기를 실행 시간에 더하지 않고 계측을 위해 shared/notify를 호출하지 않는다. VM 폐기 전 미저장 표본은 유실될 수 있으며 외부 오류 수집과 독립적이다.

다음은 남아 있는 구현 한계다. 세션 Resume의 `run` 이름 충돌은 후속 Codex parity 작업에서 수정하고 양쪽 에이전트의 Resume/Fork 핸들러를 검증했다. [추가 검증 범위](../codex-parity.md).

| 위치 | 현재 구현/한계 | 이식 시 처리 |
|---|---|---|
| `worktree.js`의 dropBranch | 문서는 새 브랜치만 정리한다고 설명하지만 코드는 `newBranch === false`만 명시적으로 보존. 미기록 값은 merged 검사 후 삭제 가능 | 소유/출처 미확인 브랜치는 보존하는 보수적 동작 권장; 기존 행동과 달라짐을 기록 |
| worktree 파일 복사 | remote는 생략, helper 실패가 생성 오류로 전달되지 않음 | 로컬 지원을 명시하고 부분 준비 실패를 표시 |
| usage steady | live와 snapshot을 섞을 때 live 값을 seen 캐시에 반영하지 않아, 오래된 snapshot 보정값이 나중에 다시 선택될 수 있음 | 출처·관측 시각·reset 경계로 일관된 병합을 설계하고 추가 사례로 검증 |
| installer | 사전·사후 check, mod별 백업/복구와 실패 코드 지원. 전체 번들 트랜잭션은 아니며 파일 교체 중간 상태를 호스트가 볼 수 있음 | 런타임 이후 비동기 오류는 별도 화면·로그 검증. 번들 전체 원자성은 추가 설계 필요 |
| 이식 검증 전체 | 문서·synthetic fixture 작성과 정합성 검증만 수행 | 모든 기능이 다른 앱에서 동작한다고 선언하지 않는다 |
