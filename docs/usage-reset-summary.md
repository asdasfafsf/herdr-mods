# 사용량 리셋권 요약 UI

사용량 UI는 개수를 먼저 보여 주고 상세는 사용자가
펼쳤을 때만 구성한다. 조회 함수, Python 수집기, 리셋 실행 함수와 기존
리셋 요청 프로토콜은 변경하지 않는다.

## 표시 동작

- 상세창을 열 때마다 Reset credits는 닫혀 있다. `Show details` / `Hide details`,
  방향 표시, 행 전체의 hover·키보드 focus 표시를 함께 사용한다. 일반 h_flex
  래퍼에 유지되는 focus handle, Tab 진입, Enter/Space 핸들러와 상태 스타일을
  둔다. 네이티브 AccordionTrigger는 pointer 변경과 expanded 상태를 맡는다.
  Header/Panel에는 각각 고정 ID를 지정한다.
- 닫혀 있을 때는 개수 또는 `Unavailable`만 표시한다. 제목·설명·지급일·만료일·
  개별 상태·조회 시각·사용 버튼은 상세 패널을 펼쳐야 나타난다. 개수는 없음을
  의미하는 0과 알 수 없음을 의미하는 null을 구분한다.
- 개수 tooltip에는 리셋권 자체 `resetCredits.updated`의 `as of`를 표시한다.
  사용량 데이터가 더 최신이어도 리셋권 조회 시각과 혼동하지 않는다.
- 갱신이나 테마 변경으로 다시 렌더해도 현재 펼침 상태는 유지한다. 이 상태는
  팝업 인스턴스에만 있으며 저장하지 않는다.
- 팝업에 요청하는 높이는 사용량 항목 수와 접힌 요약 행으로 계산한다(최대 680px).
  실제 native 창 높이는 내용의 최소 크기에 따라 달라질 수 있다.
  펼침은 같은 창의 세로 스크롤 안에서 이뤄진다. 제목·설명은 줄바꿈하고,
  개별 카드가 줄어들어 겹치지 않게 한다. 접으면 상세 트리가 제거된다.
- 좁은 바에서는 리셋권 개수와 Refresh 영역을 확보한다. 사용량 항목이 넘치면
  그 부분만 가로 스크롤한다. 개수는 `↺ 0`, 조회 불가는 `↺ —`로 표시한다.
- 새 색상 상수나 팔레트 설정은 추가하지 않는다. 배경·경계·문자·주의 표시는
  호스트의 기존 의미 토큰으로 그린다.

## 안전한 검사

```sh
node --check mods/usage-bar/main.js
node --check tests/usage-render.mjs
node tests/usage-render.mjs --native
git diff --check
```

`tests/usage-render.mjs`는 렌더 전용이다. 실제 초기화·조회 타이머를 시작하지
않고 합성 데이터를 주입한다. 호출 가능한 UI 이벤트는 아코디언 펼침·접힘과
팝업 진입 설명 생성뿐이다. 아코디언의 키보드 이벤트도 해당 래퍼의 핸들러에만
직접 전달한다. 리셋권 선택·확인·실행, Refresh, 실제 overlay 열기,
세션 메시지·승인은 호출하지 않는다. 사용 버튼은 렌더만 하며 Node 검사에는
해당 콜백을 보관하지 않는다. 호스트 실행 진입점은 호출 시 실패하도록 막는다.

순수 UI 검사는 다음을 확인한다.

- 최초 닫힘, 펼침·접힘, 새 인스턴스 재진입, 데이터 재렌더 시 펼침 상태 유지.
- Enter/Space와 키 반복·modifier 처리, pointer로 펼칠 때 래퍼 포커스 요청.
- 사용량과 리셋권의 조회 시각이 다른 경우 tooltip이 각각의 시각을 사용함.
- 조회 불가·잘못된 개수·0개·개수만 제공·일부 목록·만료·무기한·긴 12개 목록.
- 닫힌 패널은 개별 리셋권 데이터에 접근하지 않고 상세나 버튼을 구성하지 않음.
- 긴 제목·설명에 줄바꿈을 적용하고 카드가 축소되지 않음. 상세 목록은 높이를
  제한한 세로 스크롤의 자손이고, 접힌 트리는 최초 요약 트리와 동일함.
- 360/480/720/1200px 구성에서 바의 폭 예산, 사용량 가로 스크롤, 스크롤 밖의
  개수 표시와 축소되지 않는 Refresh, 목록 길이에 독립적인 팝업 높이.
- 합성 light/dark와 저장소의 Chiikawa 팔레트에서 의미 토큰을 그대로 전달함.

`--native`는 임시 폴더에 생성한 모듈에 `herdr-app check`를 실행한다.
세 팔레트별 7개 상태의 접힘·펼침 42건과 네 너비의 바 12건, 총 54건이다.
이 명령은 네이티브 요소 설명을 검증하며 앱 설치나 실제 창을 열지 않는다.
임시 폴더는 종료 시 제거한다.

## 검증의 한계

위 검사는 **실제 픽셀 배치·스크린샷 검증이 아니다**. `herdr-app check`는
eager native element를 검사하지만 실제 레이아웃·스크롤·키보드 입력·스크린리더를
구동하지 않는다. **Synthetic 속성·핸들러 검사로 네이티브 접근성이나 좁은 폭의
실제 가시성을 검증했다고 주장하지 않는다.** 실앱에서의 글꼴 폭, 스크롤 후 접힘 위치와 포커스, 확대 배율별
가시성은 통합 설치 후 별도 확인이 필요하다. light/dark는 토큰 전달을 검증하는
합성 팔레트이며 실제 호스트 팔레트의 픽셀 검증으로 주장하지 않는다.

호스트 소스 스냅샷 `b67715e8`의 `vendor/gpui-kit/crates/shell/src/materialize/components/accordion.rs`를
읽어 확인했을 때 Trigger의 accessibility label·상태 스타일·focus/key 바인딩은
전달되지 않는다. 따라서 지원되는 일반 래퍼로 옮겼으며, Header/Panel의 ID를
통해 heading/region이 구성되도록 했다. 실제 접근성 트리와 포커스 이동의 최종
확인은 메인 통합 세션의 disclosure 화면 검토 범위다.

리셋권 사용은 실제와 mock 모두 실행 검증하지 않는다. 위 검사 명령은 앱/core 재시작,
실제 세션 테스트 메시지·승인 전송, 앱 설치나 main merge를 수행하지 않는다.


## 통합 후 실제 화면 확인 (2026-11-15)

`c686b23`을 설치하고 CUA로 실행 중인 Chiikawa 팔레트에서 확인했다.
하단 개수와 별도 조회 시각 tooltip, 최초 접힘, pointer 펼침, Space 접힘,
Enter 펼침, 상세 목록 스크롤, 닫았다 다시 열 때 접힘을 확인했다.
실제 창은 펼칠 때 높이가 조금 늘었으며 목록은 내부에서 스크롤됐다.
리셋권 선택·사용 버튼이나 Refresh는 누르지 않았다.

AX 출력에는 heading과 button이 나타났지만 버튼 이름·expanded 값은 노출되지
않았다. 이 관찰만으로 스크린리더 지원을 검증했다고 볼 수 없다.
다른 팔레트·확대 배율·좁은 화면은 위 합성 렌더 검사 범위다.
