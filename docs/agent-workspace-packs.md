# Agent workspace: 설치와 커스텀 팩 설계

앱 색상, 에이전트 캐릭터·장면 팩, Cards/Village 표시 방식을 각각 선택한다.
에이전트 화면은 원래 작업공간과 실제 터미널을 공유한다. 팩을 바꿔도
현재 세션·포커스·초안·분할 비율을 유지한다.

이 문서는 **현재 지원하는 설치 방법**과 **다음 구현의 설계**를 구분한다.
외부 팩 가져오기·커스텀 편집·팩 관리 UI는 아직 구현되지 않았다.
현재 변경은 실행 중인 앱에 설치하지 않은 리뷰용 feature 브랜치다.
실행 앱과 분리한 회귀검사 명령과 검증 한계는
[별도 테스트 안내](agent-workspace-testing.md)에 정리했다.

## 적용하면 보이는 화면

| 사용자가 바꾸는 것 | 위치 | 결과 |
|---|---|---|
| 앱 색상 | Settings → Look | 앱·카드·말풍선·터미널의 팔레트 변경 |
| 캐릭터와 배경 | 공통 Agents 헤더의 Pack | Plain 또는 Chiikawa 선택; 앱 색상 유지 |
| 표시 방식 | 같은 헤더의 Cards / Village | 같은 세션을 카드 또는 마을로 표시 |
| 터미널 크기 | 장면과 터미널 사이 경계 | 원래 native terminal tree의 비율 변경 |
| 일시적인 움직임 정지 | Options → Pause animation / Resume animation | 현재 화면의 애니메이션 정지·재개 |

예를 들어 Graphite + Chiikawa + Village를 선택하면 앱과 말풍선은 다크 색상,
마을과 캐릭터는 치이카와 리소스를 사용한다. 짱구 팩을 추가한 뒤에도 같은
컨트롤과 상태·말풍선·이동·선택·드래그를 쓴다. 짱구 리소스 수집은 범위 밖이다.
상단 Terminal/Agent 전환 줄이나 별도의 작업공간은 만들지 않는다.

## 현재 지원하는 설치·업데이트

저장소 루트에서 아래처럼 필요한 번들만 선택한다. 먼저 dry-run 결과를 확인한다.
이 문서의 명령은 사용자 설치 절차이며, 이번 작업에서 실행 앱에는 적용하지 않는다.

```sh
./install.sh agents --dry-run
./install.sh agents
```

`agents`는 공통 화면과 Plain·Chiikawa 리소스를 포함한다. 기존 sidebar가 없거나
숨겨져 있어도 현재 작업공간에 장면/터미널 split을 구성한다. 다른 번들은 필요 없다.
치이카와 **앱 색상도** 원하면 별도로 설치하고 Settings → Look에서 선택한다.

```sh
./install.sh chiikawa --dry-run
./install.sh chiikawa
```

특정 레이아웃 대상 설치는 `./install.sh agents --layout NAME --dry-run`으로
검토하고 같은 명령에서 `--dry-run`을 빼서 실행한다. 기본 명령은 현재 레이아웃을
사용한다. Herdr 제공 레이아웃은 복제본을 만들며, 설치 출력의 전환 안내를 따른다.
사용자가 이미 지정한 단축키는 `--replace-keys`를 명시하지 않으면 유지한다.

업데이트는 사용자가 선택한 릴리스/커밋의 소스를 받은 다음 같은 번들 설치를
다시 실행한다. 설치기는 mod 교체 전후 검사와 이전 파일 복구를 제공하지만,
전체 번들을 하나의 원자적 작업으로 되돌리는 설치기는 아니다.
상세 동작은 [설치 안내](../README.md#설치하면-무엇이-바뀌나)와
[실패 복구](recovery-reliability.md)를 따른다.

**설치된 `mods/agents-plus` 파일은 커스텀 원본으로 사용하지 않는다.**
현재 설치기는 소유한 mod의 코드·리소스를 업데이트 때 교체한다.
지금 새 팩을 만들려면 별도 checkout에서 [기여자용 템플릿](../mods/agents-plus/themes/TEMPLATE.md)을
따라 리소스·데이터 모듈·registry를 추가하고 검증 후 설치해야 한다.
이는 일반 사용자의 독립적인 팩 가져오기 기능과 다르다.

## 다음 구현: 사용자 흐름

일반 사용자는 소스나 JSON을 편집하지 않아도 팩을 선택하고 관리할 수 있어야 한다.
기여자용 템플릿은 고급 제작 경로로 계속 제공한다.

1. **엔진 설치:** `agents`만 설치해 시작한다. 앱 테마 설치는 별도 선택이다.
2. **팩 가져오기:** Pack 메뉴의 `Manage packs` → `Import folder`에서 로컬 팩
   폴더를 고른다. 1차 버전은 폴더를 지원한다. ZIP 자동 추출·원격 마켓은 이후 범위다.
3. **미리보기:** 이름·제작자·버전·출처와 합성 세션으로 만든 Cards/Village를 보여준다.
   파일을 검사한 뒤 `Install`할 수 있다. 설치만으로 현재 팩을 바꾸지는 않는다.
4. **적용:** 설치된 팩에서 `Use pack`을 누르면 현재 장면에 적용한다.
   원래 세션·초안·포커스·필터·분할은 그대로 둔다.
5. **간단 커스텀:** `Customize`에서 포함할 캐릭터를 선택한다. 팩의 원본은
   수정하지 않고 사용자 설정을 저장한다. 원본 값 복원은 그 설정만 지운다.
   팩의 캐릭터를 모두 제외하는 선택은 허용하지 않고 Plain 선택을 안내한다.
6. **새 팩 제작:** `Duplicate as my pack`은 고유 ID를 가진 별도 로컬 팩을 만든다.
   원본의 출처 정보도 남긴다. 폴더 열기·검증·미리보기·내보내기를 제공한다.
   배경 레이어·프레임 시간 등 고급 수정은 manifest로 한다. 그래픽 편집기는 범위 밖이다.

팩 수가 늘어나면 공통 헤더에는 `Pack: Chiikawa` 버튼 하나를 두고 목록/관리
팝업을 연다. Cards/Village는 헤더, Pause animation은 Options에 남는다.
기존 Options의 검색·상태·출처 필터와 팩 관리 화면을 섞지 않는다.

## 소유권과 저장 위치

다음 경로는 **제안된 계약이며 아직 로더·설치기가 구현되지 않았다.**
기본 루트는 `appHome()`이고 `HERDR_APP_HOME`을 쓰는 격리 환경도 같은 구조다.

```text
mods/agents-plus/                         # 설치기가 관리하는 공통 엔진·내장 팩
agent-packs/packages/<id>/<version>/      # 검증한 외부 팩 원본; 불변 버전
agent-packs/catalog.json                  # 설치된 팩과 사용할 버전
agent-packs/preferences.json              # 팩별 캐릭터 포함 목록 등 사용자 override
agent-packs/drafts/<id>/                   # 사용자가 복제해 편집하는 팩 원본
agent-packs/staging/                      # 검증 중인 파일; UI에 노출하지 않음
```

엔진 업데이트·재설치는 `agent-packs/`를 수정하거나 삭제하지 않는다. 팩 업데이트는
사용자 override를 유지하고, 사라진 캐릭터 ID는 건너뛰되 관리 화면에 알려준다.
유효한 캐릭터가 하나도 남지 않으면 팩의 기본 목록을 사용하고 복원 이유를 표시한다.
제작 중인 drafts는 어떤 업데이트에서도 교체하지 않는다.

명시적 선택은 기존 `ag.resourcePack`, 표시 방식은 `ag.presentation`을 유지한다.
과거 선택을 가져오는 `ag.resourcePackMigration`은 명시적 새 선택보다 낮은 우선순위다.
native 테마 fallback을 처음 한 번 저장하고, 늦게 마운트한 기존 standalone overview의
명시적 선호가 있으면 자동 fallback보다 우선한다. 이후 앱 색상 변경은 팩을 바꾸지 않는다.
여러 standalone 선호가 충돌하면 먼저 확인된 명시적 legacy 선호를 사용한다.
사용자가 새 Pack 컨트롤에서 선택한 값은 모든 legacy 선호보다 우선한다.

## 외부 팩 형식과 공통 엔진 연결

외부 팩은 `pack.json`과 이미지 파일로만 구성한다. JavaScript·shell·hook을
실행하는 플러그인이 아니다. 엔진이 검증된 JSON을 기존 resource-pack 정의로
정규화해 동일한 렌더러에 전달한다. 네이티브 테마 ID·팔레트 정책은 팩에 넣지 않는다.

새 manifest에 필요한 필드는 다음과 같다. 현재 JS 데이터 템플릿은 이 형식으로
옮길 수 있도록 호환 로더를 거치며, 기여자가 행동 코드를 복사할 필요는 없다.

| 필드 | 계약 |
|---|---|
| `schemaVersion` | 최초 값 1; 모르는 버전은 설치하지 않고 필요한 버전 안내 |
| `engineApi` | 지원하는 팩 API 세대; 앱 버전과 별도 관리 |
| `id`, `version` | 안정적인 namespaced ID와 팩 버전; 내장 ID는 예약 |
| `label`, `author`, `source`, `license` | 표시 이름과 출처·배포 조건을 보존 |
| `residents`, `sprites`, `facing` | 기존 캐릭터·크기·시간·방향 메타데이터 |
| `scene`, `layout` | 선택적인 장면과 최초 표시 방식; 사용자 선택을 덮어쓰지 않음 |

팩의 이미지 경로는 팩 내부 상대 경로만 허용한다. 설치기가 실제 경로를 만든다.
파일 누락, 경로 이탈/심볼릭 링크, 중복 ID, 잘못된 좌표·크기·프레임 시간, 지원하지
않는 형식·API, 이미지/프레임/총 용량 상한을 설치 전 검증한다. 파일이 요구하는
실행 코드나 네트워크 요청을 허용하지 않는다. 원본 픽셀을 자르거나 재인코딩하지 않는다.
방향 wrapper가 필요하면 공통 생성기가 원본 PNG를 그대로 포함해 만든다.

내장 팩과 외부 팩은 하나의 registry 인터페이스를 사용한다. 외부 목록은 렌더 중에
읽지 않고 비동기로 읽어 마지막 유효 스냅샷을 교체한다. 로드 중에도 기존 장면과
세션은 유지한다. 팩 데이터에는 상태 판정·메시지 전송·승인·포커스 함수가 없다.

## 설치·업데이트·실패·제거

| 작업 | 동작 |
|---|---|
| 최초 설치 | staging으로 복사 → 전체 검증 → 버전 폴더 확정 → catalog 원자적 교체 |
| 같은 ID·버전 | 동일 내용은 변경 없음; 다른 내용은 덮어쓰지 않고 새 버전 또는 복제 요청 |
| 새 버전 | 이전 버전을 남겨 설치; 미리보기 후 새 버전 적용; 실패하면 이전 버전 유지 |
| 검증 실패 | 현재 catalog·팩·사용자 설정을 수정하지 않고 파일/필드 단위 오류 표시 |
| 동시 관리 작업 | 팩 관리기에서 직렬화하고 catalog 변경 충돌을 검출 |
| 파일 손상/누락 | 손상을 탐지하면 이미지 파일까지 유효한 이전 버전/내장 팩으로 복구; 정상 리소스가 없으면 현재 실행 중에도 Plain 표시 및 관리 링크 |
| 선택된 팩 제거 | 삭제 결과를 먼저 표시; 사용자가 제거하면 Plain으로 표시하되 저장된 ID/커스텀은 유지 |
| 커스텀까지 제거 | 팩 제거와 별도 선택; 해당 팩의 사용자 override만 삭제 |
| 엔진 제거 | 자동 uninstall은 아직 없음; 사용자 팩·원래 세션을 삭제하는 동작으로 대체하지 않음 |

미리보기는 실제 세션에 연결하지 않는다. 팩 설치·전환·제거 때문에 터미널을
새로 만들거나 세션 메시지·승인 입력을 보내지 않는다. 앱/코어 재시작도 요구하지 않는다.
마지막 유효 JSON 스냅샷만으로 이미지 복구를 보장하지 않는다. watcher/재검증에서
파일 문제를 감지하면 실제 이미지가 남아 있는 버전을 확인한 뒤 전환한다.

## 구현 순서와 완료 기준

1. **현재 기반:** 팔레트/팩 분리, 공통 엔진 재사용, 명시적 선택과 legacy migration
   우선순위, Plain fallback. 독립 코드 리뷰 지적을 수정하고 회귀검증한다.
2. **패키지 계약:** JSON 스키마·validator·격리된 저장소·catalog·loader를 구현한다.
   유효하지 않은 팩이 기존 장면을 손상하지 않고 엔진 재설치 후에도 커스텀이 남아야 한다.
3. **관리 UI:** 가져오기·합성 미리보기·적용·캐릭터 선택·복제·내보내기·제거를 붙인다.
   신규 팩이 상태·말풍선·이동·드래그·포커스·split 엔진 변경 없이 동작해야 한다.
4. **배포 검증:** 격리된 앱 홈에서 최초 설치/업데이트/실패 복구/제거를 검증한다.
   native initial render 검사 외에 실제 레이아웃·폭·팝업·이미지 표시 확인이 필요하다.
   실행 중인 사용자 앱에 적용하는 작업은 현재 범위에 포함하지 않는다.

패키지 계약을 구현하기 전에 호스트에서 앱 루트 아래 `agent-packs/` 이미지 표시,
버전 경로 변경 시 캐시 무효화, watcher 갱신을 격리 환경으로 확인한다. 현재 native
`check`는 초기 렌더만 검사하므로 이 지원을 검증했다고 간주하지 않는다.
지원되지 않으면 사용자 원본은 위 경로에 두고 별도 생성 자산 캐시로 연결한다.
리소스 크기 상한은 기존 내장 팩을 통과시키는 측정값으로 정하고 schema/오류에 명시한다.

각 단계는 구현한 범위로 Conventional Commit을 만들고 feature 브랜치에만 push한다.
독립 리뷰의 지적이 해결되기 전에는 그 단계를 완료로 표시하지 않는다. 리셋권
실행/테스트(mock 포함), 실제 세션 테스트 메시지·승인, main 수정·push는 하지 않는다.
