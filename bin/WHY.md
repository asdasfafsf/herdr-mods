# hm 과 herdr 스킬을 만든 이유

에이전트(Claude Code·Codex)가 말로 시킨 일을 사이드바·메뉴와 똑같이 하게. `bin/hm` 명령과 `skills/herdr/SKILL.md`(commands 번들).

## Herdr 기본
Herdr 기능은 에이전트가 `herdr-app do <명령>`(창: space·탭·분할·레이아웃)과 `hc`(터미널·에이전트)로 부를 수 있고, 각자 `--skill` 사용법이 있다. mod 명령은 `herdr-app do <mod>.<명령>` 으로 보낼 수 있지만 결과를 돌려받지 못하고 목록에도 안 나온다.

## 모자랐던 것
- 우리가 더한 기능(워크트리 만들기·핀·Sleep·메모·세션·한도…)은 클릭으로만 됐다.
- 에이전트가 git 으로 직접 워크트리를 만들면 이름·링크·setup·space 가 빠져, 버튼으로 만든 것과 달랐다.
- 에이전트가 이런 기능이 있는지 알 길이 없었다.
- UI 오류가 다음 렌더에서 사라지면 발생 시각·스택을 나중에 확인할 수 없어서 사람이 오류 화면을 매번 복사해야 했다.

## 더한 것
- `hm`: `ls`, `new`(Herdr 에 안 연 레포도 이름·경로로), `add`, `clone`, `project`, `go`, `sleep`, `pin`, `archive`, `set`, `rm`, `clean`(창 없이 바로: 사람이 시킨 게 곧 확인. 안 올린 변경이나 작업 중인 에이전트가 있으면 지우지 않고 이유를 돌려줌, `--force` 로만), `term`, `sessions`, `resume`, `outside`, `usage`, `sort`, `pin-agent`, `restore`. 대상은 생략(지금 있는 워크트리)·이름·브랜치·경로. 버튼과 같은 함수(`lib/worktree.js` 등)를 부른다. `hm new` 는 결과를 `wt.results` 에서 받아 경로나 실패 이유를 출력.
- `herdr` 스킬: "Herdr 에선 워크트리를 git 이 아니라 `hm new` 로", 사람이 하는 말 → 명령 표, Herdr 원래 기능(`herdr-app do`·`hc`) 안내. `~/.claude/skills/herdr`, `~/.codex/skills/herdr` 에 설치.

## 원칙
`hm logs --watch`는 앱 밖에서 오류를 파일에 남기고 `hm logs`로 나중에 읽게 한다. 같은 오류는 묶고 발생·복구·연결 실패를 구분한다. 조회 사이의 짧은 오류까지 모두 잡는다고 보장하지 않는다. [UI 진단](../docs/ui-diagnostics.md)에 실행·보존·이식 기준이 있다.

오류 스택만 보고 느린 구간을 추측하지 않도록 `hm logs --render`로 Agents Plus의 구간별 시간·데이터 규모·미완료 관측을 읽는다. 계측은 렌더 안의 메모리 집계와 밖의 묶음 저장으로 나누어 기록 때문에 다시 그리는 일을 만들지 않는다. VM 폐기 전 미저장 자료까지 복원하는 기능은 아니다.

문서 보기(`md`), 보기 설정·색(`option`, `color`), 세션 이동·변환(`resume --into`, `translate`)도 명령으로 제공한다. 전체 목록과 실패·시간 초과 조건은 [이식 연동 명세](../docs/porting/integrations.md), 기능별 결과는 [합격 사례](../docs/porting/acceptance.md)를 따른다.

새 기능은 핵심을 `lib/` 에 두고 버튼과 `hm` 이 같이 부르며, 스킬 표에 한 줄 더한다. 확인 창과 알림 토스트는 사람이 버튼을 누를 때만 쓴다. 에이전트 쪽은 창도 알림도 띄우지 않고(에이전트가 대화로 알린다), 잃을 게 있으면 하지 않고 이유를 돌려줘 에이전트가 묻게 한다.

## 걷어낼 조건
기능별로: Herdr 가 그 기능을 기본으로 하고 명령으로 부를 수 있게 되면, `hm` 의 그 명령과 스킬 표의 줄을 Herdr 명령으로 바꾼다.

## 옮길 때 가져갈 것
스킬의 "사람이 하는 말 → 명령" 표: 다른 도구에서도 같은 요청 목록을 그 도구의 명령으로 채우면 된다.
