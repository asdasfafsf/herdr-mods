# agents-plus 를 만든 이유

Agents 목록. Herdr 에 딸린 `agents` 의 복제본(원본은 `upstream/agents/`).

## Herdr 기본
Herdr 가 띄운 에이전트를 상태별·우선순위로 보여준다. 본 done 은 떠날 때까지 Done 에 남는다.

## 모자랐던 것
- Orca·iTerm·VS Code 등 Herdr 밖에서 도는 Claude·Codex 가 안 보인다(Herdr 로 옮기는 중에도 다 한곳에서 보고 싶음).
- 보고 있는 탭의 에이전트가 done 이 되면 아래로 밀려 찾기 어렵다.
- 목록이 많을 때 다시 그리기가 중단되면, 지금 답하거나 승인해야 할 에이전트를 목록에서 확인할 수 없다. 작업이 많아져도 목록을 읽을 수 있어야 하고 이름·상태 변경도 바로 반영돼야 한다.
- 오류 스택만으로는 어느 구간에 시간이 들었는지 몰라 추측으로 최적화하게 된다. 평소 구간 시간과 당시 목록 규모를 비교할 수 있어야 한다.

## 더한 것
- `agent-mode.js`는 한 작업공간의 `workspace-views` stack에서 기존 active tab과 에이전트 블록 중 하나를 표시한다. 설치 시 기존 개인 레이아웃에 전환 바와 stack을 추가하며 새 Agent 레이아웃을 만들지 않는다. 터미널과 에이전트는 host 포커스를 공유하고 에이전트 표시 중에는 터미널이 보이지 않는다. `themes.js`는 색상 토큰·캐릭터 목록·기본 보기 방식의 단일 정의이며 카드/마을은 동일한 세션 수집, 검색, 메시지 기능을 공유한다. 테마는 네이티브 Settings에서 앱 전체에 적용하며 터미널/에이전트 표시 전환에도 유지한다. Light와 Dark의 선택을 별도로 보존하고, 예전 코드가 치이카와 한 테마로 고정한 설정만 저장된 다크 테마로 한 번 복구한다. 기본 테마를 선택하면 저장한 원래 색상을 복원한다. seen은 항상 남기고 idle만 포커스한 세션을 표시한다. 기존 독립 overview 탭은 호환한다. 이전 실험의 `herdr-agents` 레이아웃은 비활성 상태이고 정확한 소유 구조가 확인될 때만 백업 후 설정 목록에서 제거한다.
- 마을에서는 캐릭터 아래에 세션명과 프로젝트를 상시 표시하고 hover로 전체 이름·브랜치·주소를 확인한다. 선택 상세에는 주소와 브랜치를 표시해 비슷한 이름의 세션도 구별한다. `village-chat.js`는 선택한 에이전트에게 `hc send`로 직접 말을 건다. 네이티브 Textarea를 선택 이벤트에서 세션별로 만들고 초안과 전송 상태를 보존한다. 버튼/⌘Enter만 전송하며 plain Enter는 줄바꿈이다. 전송 전 최신 host agent/terminal과 `hc get`의 실행 상태를 확인하고, 셸·종료·상태 불명·blocked/error에는 전송하지 않는다. 외부 세션은 먼저 Herdr로 이어 연다. 전달 직전 idle/working 조건을 사용하고 `--force`나 자동 재시도는 하지 않는다. 90초 실행 제한으로 Core의 사용자 초안 대기 시간을 허용한다. 성공은 전달 완료만 뜻하며 답변 완료는 기존 상태/말풍선이 표시한다. 전송 중 편집하거나 다른 캐릭터를 선택해도 비동기 결과가 새 초안을 지우지 않는다. 초안은 메모리에만 있고 탭 종료/모드 재로드 시 사라진다. 메시지 전송 검증은 가상 transport를 사용하며 실제 세션에 테스트 메시지를 보내지 않는다.
- 기존 독립 Agent view 탭도 호환한다(접힌 사이드바의 레이어 아이콘은 같은 작업공간의 에이전트 표시로 전환한다). 모든 프로젝트의 현재 부모 에이전트·Herdr 밖 Claude/Codex 세션을 카드로 표시하고, 상태·현재 작업·프로젝트·브랜치를 자동 갱신한다. 너비에 따라 1–4열, 한 페이지에 24개를 표시하며 이름·작업·프로젝트·브랜치 검색과 상태·출처 필터를 제공한다. 카드는 해당 pane/외부 이어 열기로 연결된다. 과거 종료된 세션 기록은 포함하지 않으며, 보기만 해서는 사이드바 순서나 읽음 상태를 변경하지 않는다.
- 기본 테마와 치이카와 테마는 `renderAgentView`의 세션 수집·검색·필터·정렬·24개 페이지·이동 동작을 공유한다. 기본 테마는 기존 카드를, 치이카와 테마는 `village.js`의 마을을 표시한다. 공식 Pocket 초원/마을 배경과 그루터기, 애니메이션 공식 나무를 겹쳐 장면을 만든다. 치이카와·하치와레·우사기는 세션별로 고정된 캐릭터를 유지하고, 마을 안에서 각자 목적지를 골라 이동하다 쉰다. 서로 겹치려 하면 방향을 바꾼다. 화면에 보이는 캐릭터는 선택·hover·상태와 관계없이 계속 돌아다니며 도착 후 휴식은 0.1–0.35초다. 현재 상태는 캐릭터 위의 작은 색 점과 공통 영어 상태명으로 표시한다. blocked/done일 때만 입력·승인 요청 또는 읽지 않은 답변의 실제 미리보기를 캐릭터와 함께 움직이는 말풍선으로 보여준다. seen/idle/working에는 말풍선을 띄우지 않으며 기존 host 읽음 상태를 따른다. 마을 표시나 상세 선택만으로 읽음 처리하지 않는다. 선택한 한 명의 작업을 아래 상세에 표시하며 `세션 열기`로 이동한다. 검색·상태·출처·새로고침은 접을 수 있는 검색·필터 영역에 있다. 창이 좁거나 에이전트가 많으면 마을을 세로로 늘려 스크롤한다. 테마 전환 시 검색·필터·페이지를 초기화하지 않는다. 전체 테마는 네이티브 Settings를 따르고, 기존 독립 overview의 테마 선택만 `overview.theme`에 저장한다. 움직임은 새 화면에서 항상 켜지며 Pause는 현재 화면에서만 유지한다. 애니메이션은 원본 APNG의 반투명 가장자리와 프레임 타이밍을 유지하며, 숨겨진 pane과 사용자가 일시정지한 동안에는 멈춘다. 화면에 보이면 창의 포커스와 무관하게 재생하고 host/shared 스냅샷은 2초 동안 재사용한다. 출처는 `assets/chiikawa/SOURCES.md`에 있다.
- 공유 Codex 서버는 PID 하나에 여러 세션을 가질 수 있다. 열린 writer별로 나누고 Herdr 복원 기록에 있는 ID는 제외한다. 원래 터미널 앱을 확정할 수 없는 것은 `Codex server`로 표시하며, 행 ID도 PID 대신 세션 ID를 쓴다.
- 바깥 에이전트(`outside.py`: Claude 는 `~/.claude/sessions`, Codex 는 `ps`·`lsof`)를 같은 상태 묶음에 앱 태그와 흐린 아이콘으로. 누르면 Herdr 에서 이어 열기(이미 Herdr 에 있으면 그리로, 원래 앱의 것은 그대로).
- 맨 위 Active 묶음: 지금 보는 탭의 에이전트.
- 소식이 있을 때만 두 번째 줄: 일하는 중이면 지금 하는 일(▸ Editing main.py, Running npm test; 도구 사이에는 이번 요청에서 마지막으로 한 말, 없으면 마지막 단계 · thinking…), 기다리는 중이면 허용을 기다리는 명령(?), 끝났으면 답의 첫 줄(✓). 쉬는 에이전트는 한 줄 그대로. 각자의 세션 기록(Claude `~/.claude/projects`, Codex rollout)의 끝만 읽고, 바뀐 것만 다시 읽는다(`activity.py`, 창이 앞에 있을 때 3초마다). Orca 는 같은 정보를 Claude 훅으로 받는데, 여기선 훅 없이 기록에서 읽는다.
- 레포 · 브랜치: 마우스를 올리면, 같은 이름의 행이 둘 이상이면 행에 바로(사이드바의 `wt.trees`).
- worktrees 번들이 없으면 스스로 이어 연다(그 폴더를 담은 space 의 새 탭, 없으면 새 space).
- 렌더 한 번에 pane·워크트리·외부 행 메타데이터를 한 번씩 읽어 함께 쓴다. 행마다 전체 데이터를 다시 복사·정렬하지 않는다. 다음 렌더에는 새로 읽어 변경된 이름·경로가 묻히지 않게 한다. 재현·전후 측정은 [성능 개선 기록](../../docs/render-performance.md).
- Seen 기간·읽음 상태·보기 옵션·레포 색도 렌더당 한 번 읽는다. 작업 재개 시 지난 읽음 표시를 먼저 제거하고, 클릭·비동기 갱신은 새 값을 읽으므로 방금 한 읽음 처리나 설정 변경을 이전 스냅샷으로 덮지 않는다.
- `parentAgents`는 host agent와 terminal의 부모 관계를 한 번 확인해 사이드바·카드·마을에서 자식을 모두 제외한다. Codex 내부 thread는 조회하거나 공유하지 않는다. 사이드바의 명시적 선택 요청으로 같은 부모를 다시 클릭해도 닫은 상세창이 열리며, 필터·페이지 밖의 부모도 표시한다.
- 구간별 렌더 시간을 메모리에 집계하고 60초마다 렌더 밖에서 저장한다(`hm logs --render`). 느린 완료와 종료 기록이 없는 실행을 구분하며, 후속 실행까지의 대기 시간을 렌더 시간으로 오인하지 않는다. 기록 때문에 화면을 추가로 갱신하지 않는다. 보존·유실 조건은 [UI 진단](../../docs/ui-diagnostics.md).

- Seen: 끝난 에이전트를 보고(done → idle) 대꾸하지 않으면 2시간 동안 Working 과 Idle 사이 "Seen"(보라 테두리, 다른 상태와 겹치지 않는 색)으로 둔다. 봐 놓고 놓친 걸 Idle 더미에 묻히지 않게. 판정은 `lib/ui.js` 의 `shownStatus` 하나, 본 시각은 agents-plus 가 `ag.info[address].seen` 으로 공유. 사이드바·⌘P 도 같은 표시.
- 상태 정의는 `lib/agent-status.js` 한 곳에 둔다. 이름·우선순위·색상 역할·아이콘·기본 설명·말풍선 여부·Idle 숨김을 사이드바·카드·마을·picker에서 공유한다. 상태 표시는 모두 영어이며, 사용자와 에이전트의 실제 대화는 원문을 유지한다.
- 카드·마을 상세창의 `session-controls.js`는 선택 세션의 현재 터미널 화면과 승인 선택지를 보여준다. `hc read --lines 0`만 사용해 화면을 스크롤하지 않는다. Codex·Claude가 permission으로 보고한 숫자 메뉴와 현재 선택 표시가 모두 확인된 경우에만 선택 버튼을 제공한다. 클릭 직전에 주소·프로세스·turn·상태 시각·요청 내용·화면을 재검증하고, 같은 요청일 때만 방향키와 Enter를 보낸다. 자동 승인·재시도는 없다. 질문/auth/모르는 메뉴는 원문과 Open session을 제공한다. 현재 Core의 keys API에는 요청 ID를 조건으로 하는 원자적 전송이 없으므로 검증 직후 다른 창에서 요청을 동시에 조작하는 경쟁까지 막는다고 주장하지 않는다. 실제 승인 전송은 테스트하지 않으며 가상 transport로 검증한다.

## 걷어낼 조건
에이전트를 전부 Herdr 로 옮기면 바깥 목록은 필요 없다. Herdr 가 "지금 보는 것을 위로" 를 하면 Active 를 뺀다. Herdr 가 에이전트의 지금 단계와 마지막 답을 보여주면 두 번째 줄을 뺀다.

## 옮길 때 가져갈 것
없다(매번 프로세스에서 다시 찾는다).

- 카드/마을은 `overview-header.js`의 동일한 헤더를 사용한다. `Cards / Village`는 공통 작업공간 상단 바에서 고정된 위치로 제공하고 `ag.presentation`을 공유한다. 전체 테마는 네이티브 `settings().theme`을 읽으며 별도 선택 상태를 두지 않는다.
- 치이카와의 크림색 배경·갈색 글자·터미널 ANSI는 하나의 팔레트에서 생성한다. 치이카와를 선택할 때 터미널 대비 보정을 켜서 이미 출력된 사용자 메시지와 Edit도 읽을 수 있게 하고, Default로 돌아가면 원래 설정을 복원한다. 프로그램이 직접 출력하는 RGB 배경을 변경할 mod API는 없다. Codex의 별도 테마는 자동 원복 조건을 충족하지 못해 설치·활성화하지 않으며 Claude 설정도 바꾸지 않는다. 적용 범위와 제한은 [테마 템플릿](themes/README.md).
