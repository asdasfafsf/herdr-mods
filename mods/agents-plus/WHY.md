# agents-plus 를 만든 이유

Agents 목록. Herdr 에 딸린 `agents` 의 복제본(원본은 `upstream/agents/`).

## Herdr 기본
Herdr 가 띄운 에이전트를 상태별·우선순위로 보여준다. 본 done 은 떠날 때까지 Done 에 남는다.

## 모자랐던 것
- Orca·iTerm·VS Code 등 Herdr 밖에서 도는 Claude·Codex 가 안 보인다(Herdr 로 옮기는 중에도 다 한곳에서 보고 싶음).
- 보고 있는 탭의 에이전트가 done 이 되면 아래로 밀려 찾기 어렵다.
- 목록이 많을 때 다시 그리기가 중단되면, 지금 답하거나 승인해야 할 에이전트를 목록에서 확인할 수 없다. 작업이 많아져도 목록을 읽을 수 있어야 하고 이름·상태 변경도 바로 반영돼야 한다.
- 오류 스택만으로는 어느 구간에 시간이 들었는지 몰라 추측으로 최적화하게 된다. 평소 구간 시간과 당시 목록 규모를 비교할 수 있어야 한다.

## 더한 것
- `workspace-views`는 장면과 기존 native tab tree를 담는 하나의 resizable column이다. 상단 Terminal/Agent 전환 줄은 제거하고, 영구적인 20px 손잡이에서 원래 비율을 복원한다. 양 끝으로 드래그하면 한쪽만 표시하고, native의 24px 경계는 놓은 뒤 정확한 끝점으로 보정한다. 테마/키 명령은 이 손잡이 한 곳에서만 수신한다. 기존 stack은 소유 구조를 확인한 경우에만 변환하고 원래 터미널의 pane 옵션은 보존한다.
- 마을에서는 캐릭터 아래에 세션명과 프로젝트를 상시 표시하고 hover로 전체 이름·브랜치·주소를 확인한다. 선택 상세에는 주소와 브랜치를 표시해 비슷한 이름의 세션도 구별한다. `village-chat.js`는 선택한 에이전트에게 `hc send`로 직접 말을 건다. 네이티브 Textarea를 선택 이벤트에서 세션별로 만들고 초안과 전송 상태를 보존한다. 버튼/plain Enter로 전송하고 ⌘Enter/Shift+Enter는 줄바꿈이다. native Textarea의 Change → Submit 순서를 따라 Enter가 추가한 줄바꿈만 복구하고, 한글 조합은 native editor에 맡긴다. 이미지 파일은 명시적 전송 때만 `hc put`으로 대상 세션에 복사해 파일 참조를 보낸다. CLI의 실제 이미지 첨부는 하단 native terminal의 붙여넣기/드롭으로 처리한다. 전송 전 최신 host agent/terminal과 `hc get`의 실행 상태를 확인하고, 셸·종료·상태 불명·blocked/error에는 전송하지 않는다. 외부 세션은 먼저 Herdr로 이어 연다. 전달 직전 idle/working 조건을 사용하고 `--force`나 자동 재시도는 하지 않는다. 90초 실행 제한으로 Core의 사용자 초안 대기 시간을 허용한다. 성공은 전달 완료만 뜻하며 답변 완료는 기존 상태/말풍선이 표시한다. 전송 중 편집하거나 다른 캐릭터를 선택해도 비동기 결과가 새 초안을 지우지 않는다. 초안은 메모리에만 있고 탭 종료/모드 재로드 시 사라진다. 메시지 전송 검증은 가상 transport를 사용하며 실제 세션에 테스트 메시지를 보내지 않는다.
- 기존 독립 Agent view 탭도 호환한다. 사이드바의 중복 진입 버튼은 제거하고 split 경계와 ⌘⇧E로 장면 표시를 조절한다. 모든 프로젝트의 현재 부모 에이전트·Herdr 밖 Claude/Codex 세션을 카드로 표시하고, 상태·현재 작업·프로젝트·브랜치를 자동 갱신한다. 너비에 따라 1–4열, 한 페이지에 24개를 표시하며 이름·작업·프로젝트·브랜치 검색과 상태·출처 필터를 제공한다. 카드는 해당 pane/외부 이어 열기로 연결된다. 과거 종료된 세션 기록은 포함하지 않으며, 보기만 해서는 사이드바 순서나 읽음 상태를 변경하지 않는다.
- 사이드바가 실제 그룹 순서(고정·Active·상태 또는 프로젝트, 외부 세션 포함)를 `ag.order`로 공유한다. 카드·마을·picker는 이 순서를 소비하고 필터는 상대 순서를 보존한다. 치이카와 activity cache가 살아 있어도 포커스·고정·정렬 변경은 새 순서를 반영한다.
- 카드는 세션 제목·프로젝트/브랜치·주소와 작업 미리보기를 분리한다. `Active`는 native focus, `Selected`는 별도 상세 선택을 나타내며 상세를 닫아도 포커스 표시는 유지한다. 상태와 읽기 알림은 공통 registry에서 가져오며, 원문은 hover로 확인한다. 캐릭터는 고정 정사각형 안에 비율을 유지해 담고 카드 높이는 내용에 따라 늘어나므로 footer와 그림이 경쟁하지 않는다. 카드 선택/`Open terminal`은 같은 Agent 화면의 하단 터미널을 열고 독립 overview에서는 추가 초안창을 연다. 별도 `View details` 버튼은 없다.
- 카드와 마을은 공통 세션 수집·검색·필터·정렬·24개 페이지와 포커스를 공유한다. `resource-packs.js`의 데이터 팩이 캐릭터, 프레임 시간·방향·크기와 고정 크기 배경 레이어만 제공한다. `pack-chiikawa.js`는 치이카와 데이터이며 새 팩은 공통 동작을 복제하지 않는다. 선택한 캐릭터는 멈추고 선택 링을 표시하며, 다른 캐릭터는 이동한다. 프레임별 방향 정보를 사용해 글자는 뒤집지 않는다. 공통 `statusNotice/statusPreview`가 실제 작업 진행과 입력 요청/답변을 구분한다. 클릭·해제는 잡은 요소 자체에서도 드래그를 종료하며 다른 캐릭터에 놓을 때의 잘못된 선택을 막는다. 리소스는 원본 픽셀·시간을 보존하고 현재 전체 세션에 먼저 중복 없이 배정한다. 자세한 계약은 `themes/TEMPLATE.md`에 있다.
- 공유 Codex 서버는 PID 하나에 여러 세션을 가질 수 있다. 열린 writer별로 나누고 Herdr 복원 기록에 있는 ID는 제외한다. 원래 터미널 앱을 확정할 수 없는 것은 `Codex server`로 표시하며, 행 ID도 PID 대신 세션 ID를 쓴다.
- 바깥 에이전트(`outside.py`: Claude 는 `~/.claude/sessions`, Codex 는 `ps`·`lsof`)를 같은 상태 묶음에 앱 태그와 흐린 아이콘으로. 누르면 Herdr 에서 이어 열기(이미 Herdr 에 있으면 그리로, 원래 앱의 것은 그대로).
- 맨 위 Active 묶음: 지금 보는 탭의 에이전트.
- 소식이 있을 때만 두 번째 줄: 일하는 중이면 지금 하는 일(▸ Editing main.py, Running npm test; 도구 사이에는 이번 요청에서 마지막으로 한 말, 없으면 마지막 단계 · thinking…), 기다리는 중이면 허용을 기다리는 명령(?), 끝났으면 답의 첫 줄(✓). 쉬는 에이전트는 한 줄 그대로. 각자의 세션 기록(Claude `~/.claude/projects`, Codex rollout)의 끝만 읽고, 바뀐 것만 다시 읽는다(`activity.py`, 창이 앞에 있을 때 3초마다). Orca 는 같은 정보를 Claude 훅으로 받는데, 여기선 훅 없이 기록에서 읽는다.
- 레포 · 브랜치: 마우스를 올리면, 같은 이름의 행이 둘 이상이면 행에 바로(사이드바의 `wt.trees`).
- worktrees 번들이 없으면 스스로 이어 연다(그 폴더를 담은 space 의 새 탭, 없으면 새 space).
- 렌더 한 번에 pane·워크트리·외부 행 메타데이터를 한 번씩 읽어 함께 쓴다. 행마다 전체 데이터를 다시 복사·정렬하지 않는다. 다음 렌더에는 새로 읽어 변경된 이름·경로가 묻히지 않게 한다. 재현·전후 측정은 [성능 개선 기록](../../docs/render-performance.md).
- Seen 기간·읽음 상태·보기 옵션·레포 색도 렌더당 한 번 읽는다. 작업 재개 시 지난 읽음 표시를 먼저 제거하고, 클릭·비동기 갱신은 새 값을 읽으므로 방금 한 읽음 처리나 설정 변경을 이전 스냅샷으로 덮지 않는다.
- `parentAgents`는 host agent와 terminal의 부모 관계를 한 번 확인해 사이드바·카드·마을에서 자식을 모두 제외한다. Codex 내부 thread는 조회하거나 공유하지 않는다. 사이드바의 명시적 선택 요청으로 같은 부모를 다시 클릭해도 접힌 터미널이 열리며, 필터·페이지 밖의 부모도 표시한다.
- 구간별 렌더 시간을 메모리에 집계하고 60초마다 렌더 밖에서 저장한다(`hm logs --render`). 느린 완료와 종료 기록이 없는 실행을 구분하며, 후속 실행까지의 대기 시간을 렌더 시간으로 오인하지 않는다. 기록 때문에 화면을 추가로 갱신하지 않는다. 보존·유실 조건은 [UI 진단](../../docs/ui-diagnostics.md).

- Seen: 끝난 에이전트를 보고(done → idle) 대꾸하지 않으면 2시간 동안 Working 과 Idle 사이 "Seen"(보라 테두리, 다른 상태와 겹치지 않는 색)으로 둔다. 봐 놓고 놓친 걸 Idle 더미에 묻히지 않게. 판정은 `lib/ui.js` 의 `shownStatus` 하나, 본 시각은 agents-plus 가 `ag.info[address].seen` 으로 공유. 사이드바·⌘P 도 같은 표시.
- 상태 정의는 `lib/agent-status.js` 한 곳에 둔다. 이름·우선순위·색상 역할·아이콘·기본 설명·말풍선 여부·Idle 숨김을 사이드바·카드·마을·picker에서 공유한다. 상태 표시는 모두 영어이며, 사용자와 에이전트의 실제 대화는 원문을 유지한다.
- 통합 Agent 화면은 native terminal에서 원래의 입력·승인·스크롤·검색·복사·붙여넣기를 그대로 사용한다. `session-controls.js`는 native dock과 함께 사용하는 Card/Village에서도 보이는 blocked 부모 세션의 승인 선택지를 보여준다. 독립 overview에는 터미널 출력 미리보기도 제공한다. `hc read --lines 0`만 사용해 화면을 스크롤하지 않는다. Codex·Claude·Gemini의 provider adapter가 foreground와 permission 상태, 숫자 메뉴 및 현재 선택 표시를 확인한 경우에만 버튼을 제공한다. 상태 bridge가 없는 CLI는 메뉴 adapter만 등록해도 동작하지 않는다. 클릭 직전에 주소·프로세스·turn·상태 시각·요청 내용·화면을 재검증하고, 같은 요청일 때만 방향키와 Enter를 보낸다. 자동 승인·재시도는 없다. 질문/auth/모르는 메뉴는 원문과 Open session을 제공한다. 현재 Core의 keys API에는 요청 ID를 조건으로 하는 원자적 전송이 없으므로 검증 직후 다른 창에서 요청을 동시에 조작하는 경쟁까지 막는다고 주장하지 않는다. 실제 승인 전송은 테스트하지 않으며 가상 transport로 검증한다.

## 걷어낼 조건
에이전트를 전부 Herdr 로 옮기면 바깥 목록은 필요 없다. Herdr 가 "지금 보는 것을 위로" 를 하면 Active 를 뺀다. Herdr 가 에이전트의 지금 단계와 마지막 답을 보여주면 두 번째 줄을 뺀다.

## 옮길 때 가져갈 것
없다(매번 프로세스에서 다시 찾는다).

- 카드/마을은 `overview-header.js`의 동일한 헤더를 사용한다. `Cards / Village`는 공통 작업공간 상단 바에서 고정된 위치로 제공하고 `ag.presentation`을 공유한다. 앱 색상은 네이티브 `settings().theme`을 읽고, 별도의 `Pack` 선택은 `ag.resourcePack`에 저장한다. 앱 Light/Dark와 팩을 독립적으로 바꿀 수 있으며 팩 변경은 포커스·초안·위치·터미널 split을 보존한다.
- 치이카와의 크림색 배경·갈색 글자·터미널 ANSI는 하나의 팔레트에서 생성한다. 치이카와 앱 팔레트를 선택할 때만 터미널 대비 보정을 켜서 이미 출력된 사용자 메시지와 Edit도 읽을 수 있게 하고, Default로 돌아가면 원래 설정을 복원한다. 프로그램이 직접 출력하는 RGB 배경을 변경할 mod API는 없다. Codex의 별도 테마는 자동 원복 조건을 충족하지 못해 설치·활성화하지 않으며 Claude 설정도 바꾸지 않는다. 적용 범위와 제한은 [테마 템플릿](themes/README.md).

- 승인 선택지는 [공통 provider adapter](../../docs/approval-adapters.md)를 통해 Card/Village에 표시한다. Native dock이 있어도 보이는 blocked 부모 세션은 읽기 전용으로 polling하며, 요청 재검증·명시적 선택 전송·오류 처리는 공통 controller가 소유한다. 실제 CLI의 상태 보고/foreground 식별이 없는 경우에는 터미널로 돌아간다.
