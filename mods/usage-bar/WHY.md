하단바의 Claude·Codex 요금제 한도.

없다.

## 모자랐던 것
Claude·Codex 를 얼마나 썼는지, 언제 리셋되는지 안 보인다.

## 더한 것
- 하단바 왼쪽에 알약 하나(에이전트 사이는 얇은 선): 5시간·7일 사용률, 리셋까지 남은 시간(`resets in 3h 39m`), 정확한 시각은 hover, 누르면 자세히, 끝에 Refresh.
- Claude: Claude Code 가 상태줄에 넘기는 한도를 `hm-statusline`(상태줄 명령 앞에 끼움)이 그대로 남긴 것(`~/.herdr/usage/claude-raw.json`). Claude Code 가 보내는 창은 전부(모델별 한도를 보내면 그것도 칸으로). Claude Code 가 도는 동안 바뀐다. 없으면 ClaudeHUD 스냅샷(`display.externalUsageWritePath`, 5h·7d). 상태줄에서 빠지는 Fable 등 모델별 주간 한도는 Claude Code의 `get_usage` 제어 요청(`skip_behaviors: true`)으로 5분마다 또는 Refresh 때 직접 조회한다. 모델 호출·로그인 정보 읽기 없이 Claude가 인증을 처리하고, 훅·MCP·세션 저장·대화 기록 스캔은 끈다. 실험적 인터페이스이므로 구버전이나 조회 실패 시 스냅샷과 마지막 정상 조회값으로 대체한다(`~/.herdr/usage/claude-live.json`). 최신 전체 한도 스냅샷이 들어와도 별도 Fable 값은 유지하며, 데이터 시각은 가장 오래된 표시 항목 기준이다.
- Codex: `codex app-server` 의 `account/rateLimits/read`(읽기만)로 5분마다 또는 Refresh 때 Codex 자신에게 묻는다. 로그인 정보는 읽지 않는다. 못 물으면 세션 기록의 마지막 값(턴이 돌 때만 바뀌어서, 한도를 다 쓰면 예전 숫자가 남는다: 실제로 그랬음).
- Codex 리셋권: 기본 화면은 하단바의 `↺ 개수`와 상세창의 Reset credits 개수 요약이다. 최초·재진입 시 닫힌 네이티브 아코디언을 Show details로 펼쳐야 개별 제목·설명·상태·지급일·만료일·별도 조회 시각·사용 버튼이 나타난다. 전체 요약 행을 누르거나 키보드로 조작하며 Hide details와 방향 표시로 접힘 상태를 구별한다. 긴 제목·설명은 줄바꿈한다. 조회 불가는 `↺ —` / Unavailable, 확인된 0개는 `↺ 0` / 0 available로 구분하며, 개수만 제공되거나 상세 목록이 일부만 제공된 이유는 펼친 패널에서 알린다. Refresh·자동 갱신은 현재 펼침 상태를 유지하며 조회 실패 시 마지막 값과 별도 조회 시각을 보존한다. 상세창에서도 Refresh할 수 있다.
- 개별 리셋권의 Use credit → Use reset credit으로 선택한 권을 사용한다. 만료·사용 완료된 권은 막고 요청 중 중복 클릭과 별도 창의 동시 요청도 막는다. 선택한 ID와 재시도에 같은 idempotency key를 보내며, 결과가 불명확해도 다른 권을 자동 사용하지 않는다. 성공·초기화 불필요·이미 사용·남은 권 없음 결과를 구분하고 한도를 다시 조회한다. 개수만 조회되면 사용할 권을 확인할 수 없으므로 상세 정보를 새로 읽어야 한다.
- 사용자가 직접 사용한 요청·응답·후속 조회 결과는 `~/.herdr/usage/reset-credits.jsonl`에 기록한다(1MiB마다 `.1`로 한 번 보관). 시각·시도 키·리셋권 ID의 해시·소요 시간·결과·오류를 남기고 인증정보나 원문 ID는 저장하지 않는다. 요청 로그를 쓸 수 없으면 사용 요청도 보내지 않는다. 리셋권 사용 동작은 실제/모의 모두 실행 검증하지 않으며, 사용자가 직접 실행한 로그로 확인한다.
- Claude 스냅샷은 모든 Claude 세션이 쓰므로, 쉬던 세션이 예전 값으로 덮어쓸 수 있다. 같은 리셋 주기 안에서 오래된 값은 더 높을 수 없으니, 더 낮은 값은 예전 값으로 보고 무시한다(`~/.herdr/usage/seen.json`). 요금제를 올리면 실제로 내려가는데, 그땐 리셋 뒤에 맞춰진다. Claude 직접 조회값과 Codex 는 서버에 물은 값이라 그대로 쓴다(리셋 크레딧을 쓰면 실제로 내려감).
- 하단바의 실제 너비와 항목 수에 맞춰 `resets in` 문구를 줄인다(720px에서 4개 항목도 축약). 더 좁으면 이름·사용률만 남기고 막대·리셋 시각은 자세히 보기와 hover로 확인한다. 그래도 넘치는 사용량 항목은 가로 스크롤하고, 리셋권 개수와 Refresh는 고정한다. 상세창 높이는 사용량 창 수와 접힌 요약 행으로 정하며 리셋권 목록 길이로 늘리지 않는다. 펼친 상세는 기존 세로 스크롤 영역에 들어가고 접으면 요약 행만 남는다.
- 색은 기존 foreground/muted/dim, popover/hover/selected/border, accent/working 의미 토큰을 사용한다. Chiikawa·기본·다크 팔레트나 설정을 따로 변경하지 않는다. [렌더 전용 검증](../../docs/usage-reset-summary.md)은 조회·사용·승인 콜백을 실행하지 않는다.
- 개수 hover는 리셋권 자체 조회 시각을 표시해 최신 사용량과 오래된 리셋권 정보를 구별한다. 아코디언의 키보드·hover·focus 처리는 호스트가 지원하는 일반 래퍼에 두며, heading/region용 ID도 지정한다. 합성 속성·네이티브 설명 검사는 실제 접근성이나 좁은 폭의 픽셀 검증을 대신하지 않는다.
- Refresh는 두 직접 조회가 성공할 때만 잠깐 `Updated`를 표시한다. 일부만 성공하면 `Partial`, 모두 실패하거나 helper 실행/응답이 잘못되면 `Failed`다. 실패 이유는 hover에 보이고 마지막 정상 수치·시각은 유지한다. 캐시를 읽었다는 이유로 최신 조회 성공이라고 표시하지 않는다. 다음 수동 조회에서 회복하면 실패 표시를 지운다.
